## Line feed & Carriage return + line feed 

lf (/n) is a single line character used by linux/mac to mark the endings of the file. 
Crlf (/r/n) is a two line character used by windows to mark the ending of the file. 

Your files on disk (written by vim in Git Bash) are stored as LF. 
But Git on Windows has a setting `(core.autocrlf)` that, depending on how it's configured, may convert files to CRLF when they
land in your working directory, while still storing them as LF internally in the repository.

## Why it exists at all: 
it's meant to prevent a real headache — if everyone on a team commits with their own OS's native line endings,
git diff starts showing every single line as changed (just because the invisible line-ending character differs), even when nobody touched 
the actual content. The auto-conversion is Git's attempt to keep the repo consistent internally (always LF) while still letting Windows
tools work with CRLF locally if they expect it.
